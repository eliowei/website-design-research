# Linear 首頁：設計師摘要

> 研究日期 2026-10-01。這是 [完整研究報告](report.md) 的摘要，每一點都可以點進去看證據。

## 這個網站在做什麼
Linear 是給軟體產品團隊用的產品開發工具。首頁用四段工作流程（收需求 → 規劃 → AI 代理 → 寫碼審查）介紹產品，最後請訪客註冊或聯絡業務。

## 最值得學的設計決定
1. **外殼只用灰階，顏色留給產品和客戶**：背景 #08090A，文字只有四種灰白亮度，按鈕是白／深灰膠囊，沒有品牌色。彩色只出現在產品介面截圖裡，以及兩張見證卡（淡藍紫、螢光黃綠）上。訪客看到顏色就知道「這是產品」或「這是客戶說的話」。
   可信度：瀏覽器實際算出＋截圖取樣。→ [report §5 VP-03](report.md#vp-03)
2. **一個字族、一個標題字重，用亮度做層級**：全站只用 Inter，所有標題都是 510 字重、行高等於字級、字距收緊約 −2%；重點靠「同一句前半白、後半灰」標出，而不是換色或加粗。日期、圖號等註記另用 12px 等寬字。
   可信度：瀏覽器實際算出。→ [report §5 VP-04](report.md#vp-04)、[VP-05](report.md#vp-05)
3. **產品畫面就是主視覺，而且會「做事」**：首頁五處主視覺都是可讀的 Linear 介面，串成同一個虛構專案；AI agent 視窗會循環播放「提示 → 思考中 → 完成」。系統設定減少動態時，直接顯示完成畫面。
   可信度：瀏覽器實際操作與連拍確認；個別動畫的時長和曲線還沒量到。→ [report §5 VP-02](report.md#vp-02)、[VP-12](report.md#vp-12)
4. **四個功能段用同一套模板**：左標題、右說明＋「Learn more →」，接產品畫面，再接「Features +」清單（點開是右側規格面板）。段高幾乎一樣，上下留白各 128px。讀者讀過一段就知道怎麼讀其他段。
   可信度：瀏覽器實際算出＋截圖。→ [report §5 VP-01](report.md#vp-01)、[VP-11](report.md#vp-11)
5. **小螢幕先刪細節、保留主線**：手機上拿掉 Features 清單、Changelog 和「40,000 團隊」那行，產品畫面移到標題前面；並排卡片不疊成直列，改成橫向排列並露出下一張的邊。主按鈕三種寬度都是同樣的 44px 高。
   可信度：三個寬度的截圖＋瀏覽器量測。→ [report §5 VP-10](report.md#vp-10)、[VP-09](report.md#vp-09)

## 代價與不要照抄的地方
- 灰色小字在暗底上對比偏低，照抄前要自己檢查可讀性。
- 介面截圖充滿工程術語，適合賣給工程團隊；如果你的客群不是技術人員，這種「真實介面」會變成門檻。
- 中段完全沒有註冊按鈕，轉換只靠常駐導覽和最後一屏，適合需要先建立信任的產品，不適合想快速轉換的頁面。
- 會動的產品示範需要寫腳本並維護；分享預覽或全頁截圖時只會看到空視窗。
- 見證卡的螢光黃綠、Linear 的介面與文案是它的品牌素材，不要直接沿用。

## 還不確定的事
- 網站自己的設計 tokens（CSS 變數）沒有找到，上面的色碼和字級是從畫面反推的；要拿來當規格，先讀原始 CSS 確認。
- 捲動到各段時有沒有淡入或位移動畫，這次沒有拍到（等了 0.9 秒才開始拍）；要用逐格錄影確認。
- 手機選單展開的樣子，以及卡片列能不能用手指滑動，都還沒驗證。
