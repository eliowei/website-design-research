# Linear 設計分析

- **網址**：https://linear.app
- **研究日期**：2026-10-01
- **研究頁面**：首頁
- **類型**：SaaS 落地頁（產品開發／專案管理工具）

> 研究範圍說明：資料來自 Firecrawl（markdown、branding、links、桌機全頁截圖 1920×10024）。手機版截圖（360×5896）是 Firecrawl 2026-09-29 的快取，內容與桌機版有些微差異（例如 Hero 下方的 Logo 列）。截圖是靜態的，動畫與 hover 效果都沒辦法直接觀察。

![桌機版](screenshots/desktop.png)

## 一句話總結

近乎全黑（`#08090A`）的極簡深色介面，主視覺是「產品介面本身」：每個功能區塊都用真實感很高的 UI 模擬畫面取代插圖。版面靠大量留白、灰階層次和細分隔線撐起精品感，只有見證卡片用了亮黃 `#E4F222` 和淡藍紫兩個高彩度色塊。

## 1. 版面結構

由上到下（高度為桌機 1920 寬截圖的實測像素，約略值）：

1. **導覽列**（約 70px）：左邊 Logo，中間偏右是文字連結（Product / Resources / Customers / Pricing / Now / Contact），一條細直線隔開後接 Log in 和白色膠囊按鈕 Sign up。
2. **Hero**（約 1360px）：H1 兩行靠左對齊，下面一行副標。同一列最右邊放「New Loops →」公告連結。再往下是一張接近全寬的產品截圖（側欄 + issue 詳情 + AI 對話浮窗），截圖後方有灰色放射狀光暈，形成「舞台」效果。
3. **Logo 列**（約 250px）：OpenAI、Vercel、Salesforce、Figma、Cursor、Coinbase、Ramp 七個 logo 排成一列，下方用等寬字、全大寫的小字寫「POWERING THE COMPANIES BUILDING THE FUTURE」。
4. **價值主張**（約 1100px）：一段大字標語，前半句白色、後半句灰色。下方三欄卡片（Fig 0.1–0.3），每張是線框等角 3D 插圖加標題和說明，欄與欄之間用細直線分隔。
5. **四個功能區塊**（每塊約 1200–1600px）：Intake and integrations、Planning and monitoring、AI and automations、Build, review, and ship。四塊共用同一套模板：左欄 H2（固定斷成兩行）、右欄說明加「Learn more →」→ 寬幅產品 UI 模擬畫面（邊緣漸淡）→「Features」標籤列 + 兩欄可展開項目（+）。區塊之間用全寬細線分隔。
6. **Changelog**（約 600px）：水平時間軸，四個節點（最新一個是紅點），每個節點下有標題、摘要、等寬字日期，最後是「View all →」。
7. **客戶見證**（約 500px）：兩張大小不等的大卡片（約 7:3），左邊淡藍紫漸層（OpenAI）、右邊亮黃色（Ramp），下面一行「Linear powers over **40,000** product teams」加上「Customer stories →」。
8. **結尾 CTA**（約 650px）：置中兩行大標「Built for the future. Available today.」加兩個膠囊按鈕。
9. **頁尾**（約 500px）：小 Logo 加五欄連結，最下面是法務連結。

- **內容寬度上限與左右留白**：在 1920 寬的截圖上，內容大約從 x≈318 排到 x≈1600，約 1280px（推測 max-width 是 1280px 左右），產品畫面稍寬。
- **網格系統**：推測是 12 欄。功能區塊的標題約佔左邊 5 欄，說明從中線偏右開始；Features 列是「1 標籤欄 + 2 項目欄」；價值卡是 3 等分欄。

**可以學的地方**：同一個「標題左／說明右 → 產品畫面 → 功能清單」模板重複四次，訪客很快就能抓到閱讀節奏，製作新區塊的成本也很低。

## 2. 配色

| 用途 | 色碼 | 使用位置 |
| --- | --- | --- |
| 主色（品牌） | `#5E6AD2` | branding 抓到的品牌紫藍；首頁只出現在 UI 模擬畫面的送出按鈕、@Linear 標籤 |
| 輔助色 | `#D0D6E0` | 次要文字、淺灰說明字 |
| 背景 | `#08090A` | 全頁底色（截圖取樣與 theme-color 一致）；次要按鈕底色是 `#141516` |
| 文字 | `#F7F8F8`／灰階若干 | 標題與按鈕用 `#F7F8F8`，說明文字逐級降成灰色；標語白、灰並用 |
| 強調／CTA | `#E5E5E6`、`#E4F222` | 主按鈕是淺灰白膠囊配黑字；`#E4F222` 只用在 Ramp 見證卡，`#D8E4FF` 用在 OpenAI 卡（截圖取樣） |

- **是否有深色模式**：網站本身就是深色（colorScheme: dark），沒有看到切換淺色模式的開關。
- **漸層、陰影的使用**：Hero 後面有灰色放射光暈（中心取樣 `#787B80`）；UI 畫面四邊漸淡到背景色。主按鈕疊了 5 層低透明度陰影；次要按鈕用 `inset 0 0 0 1px rgba(255,255,255,.03)` 做出發光細邊。

**可以學的地方**：整頁 95% 灰階，彩色只留給產品內的狀態色和見證卡。少量高彩度色塊在黑底上會非常搶眼，用來強化社會證明很有效。

## 3. 字型

| 層級 | 字型 | 字級 | 字重 | 行高 |
| --- | --- | --- | --- | --- |
| H1 | Inter（heading stack 也列了 SF Pro Display） | 64px | 推測 510–600，字距收緊 | 推測 1.0–1.1 |
| H2 | Inter | 48px | 推測 510–600 | 推測 1.0–1.1 |
| 內文 | Inter | 15px | 400 | 推測約 1.6 |
| 按鈕 | Inter | 推測 13–15px | 推測 500 | — |
| 標籤／日期 | 等寬字（推測 Berkeley Mono 類，branding 沒抓到） | 推測 11–12px | 400 | — |

- 間距基準 4px、圓角基準 8px（branding spacing）。功能區塊右欄的導言約 20px（推測），形成「標題 → 導言 → 內文」三層。

**可以學的地方**：一套 Inter 靠字級、灰階和負字距撐起層次；日期、標籤這類後設資訊改用等寬字，帶出工程工具的氣質。

## 4. 元件與視覺元素

- **按鈕**：全部是膠囊形（9999px）。主要按鈕 `#E5E5E6` 底配 `#08090A` 字；次要按鈕 `#141516` 底配 `#F7F8F8` 字，加 inset 細邊。文字連結統一用「→」結尾。
- **卡片**：價值卡沒有外框，只用直線分隔；見證卡是大圓角實色底，引言大字，左下角放 Logo 和人名。
- **圖示風格**：細線單色 icon，Fig 0.1–0.3 是線框等角 3D 插圖，「Fig」編號帶出技術圖說的意象。
- **圖片／插圖／3D／影片**：主角是用 HTML 重建的高擬真 UI（看板、時間軸、散佈圖、AI 對話、程式碼 diff），markdown 抓得到其中的文字（如 ENG-2085）。沒有真人照片。

**可以學的地方**：用可讀的產品介面當插圖，比抽象插畫更能說明產品；用 HTML 重建還能保持清晰、能做動畫，也利於 SEO。

## 5. 互動與動態

- 未觀察（截圖是靜態的）：捲動動畫、hover 效果、轉場都無法確認。
- 推測：H1 在 markdown 裡重複三次，可能有逐字進場動畫或多個斷點的版本；UI 裡有「Thinking…」「Working…」「Worked for 10 sec」，推測會依序播放演示；功能項目的「+」推測是手風琴展開；Changelog 紅點推測會脈動。

**可以學的地方**：（推測）讓產品畫面自己演示一次工作流程，比影片更輕量、更有說服力。

## 6. 文案與資訊架構

- **主標語**：The product development system for teams and agents；副標「Purpose-built for planning and building products. Designed for the AI era.」
- **語氣**：自信、精簡、宣言式（A new species of product tool.／Built for the future. Available today.），強調工藝與速度。
- **CTA 文字**：Sign up、Get started、Contact sales、Learn more →、Customer stories →、View all →（markdown 另有 Open app、Download）。
- **導覽列項目**：Product、Resources、Customers、Pricing、Now、Contact ｜ Log in、Sign up。
- **資訊架構**：價值主張 → 依產品生命週期排的四大功能（對應 /intake、/plan、/ai、/build）→ Changelog（持續更新的證據）→ 社會證明 → 行動。

**可以學的地方**：功能照使用者的工作流程排序，讀起來像在講故事，每塊再各自導到深入頁。

## 7. 響應式設計

![手機版](screenshots/mobile.png)

- **手機版的版面變化**：H1 變成四行靠左；Hero 產品截圖不縮小，直接裁切；Logo 列橫向溢出（推測是跑馬燈）；三欄價值卡和見證卡都改成橫向滑動卡片（看得到下一張的邊緣）；功能區塊改成「畫面在上、文字在下」，畫面內容也換成更精簡的版本（例如 AI 區塊改成「Assign to…」選單）；這張快取截圖裡沒看到 Changelog（推測手機版有隱藏）；頁尾改成兩欄，並多了 Legal 欄。
- **導覽列在手機上的處理**：保留 Logo、Log in、Sign up，其他連結收進漢堡選單（≡）。

**可以學的地方**：不硬縮產品截圖，改成裁切或換成更簡單的 UI 片段，並用橫向滑動卡片取代多欄。

## 優點與可改進處

**優點**
- 視覺系統極度一致：單一背景色、單一字族、膠囊按鈕、細分隔線。
- 產品介面就是主視覺，不讀文字也能理解產品。
- 功能區塊共用一個模板，節奏清楚、好維護。
- 高彩度色塊只留給社會證明，焦點控制得很好。

**可改進處**
- 灰字配黑底的對比偏低（標語後半句、Features 標籤），推測可能低於 WCAG AA。
- Hero 本身沒有 CTA 按鈕，首屏只有導覽列的 Sign up。
- 頁面很長（約 10,000px），UI 細節（issue 編號、diff）對新訪客門檻高。
- 品牌色 `#5E6AD2` 在首頁幾乎看不到，辨識主要靠調性。
