- **網址**：https://linear.app　**研究日期**：2026-10-01
- **證據來源**：[observations.md](observations.md)（本報告只引用證據 ID，不重貼內容）

> **研究範圍與限制**：只研究首頁（導覽列到頁尾）。資料來自 Firecrawl 三個寬度的整頁截圖（1920／768／360）、桌機 markdown 與 branding，都是 `maxAge: 0` 即時抓取。網站直連被擋（X-01），所以**沒有任何 E1 證據**：字級與間距是從截圖量的（E3）或推估的（E5），互動狀態（X-02）、動態時長（X-03）、選單內容（X-04、X-05）都看不到。動態一節只能寫到 `[H]`，請把它當成待驗證清單。

## 1. 視覺

### Color
- [O] 整頁只有一個背景色 `#08090A`，從導覽列、Hero、各區塊到頁尾都一樣，三個寬度一致（P-01, B-colors.background, B-colorScheme）。
- [O] 文字分四級亮度，全是冷灰：`#F7F8F8`（標題、頁尾欄標）、`#D0D6E0`（區塊說明）、`#8A8F98`（副標、導覽、Learn more、頁尾連結、陳述段後半）、`#62666D`（等寬小標、Features 標籤、日期）（P-05, P-06, B-colors.secondary）。
- [O] 介面外框（「網站本身」的元件）沒有彩度：主要按鈕 `#E5E5E6`、次要按鈕 `#141516`、分隔線 `#1B1C1D`／`#1C1C1C`、Hero 光暈是中性灰 `#424548`–`#7D8186`（P-02, P-03, P-07, P-08）。
- [O] 彩色只出現在三個地方：產品 UI 截圖內（紫 `#5E6AD2` 送出鈕、青綠散點、紅綠 diff、黃色 In Progress 圖示）、見證卡（黃綠 `#E4F222`、淺藍 `#D6E5FF`）、Changelog 時間線第一個紅點 `#EB5757`（P-09, P-10, P-11, S-d01, S-d02, S-d03）。
- [O] branding 把 `#5E6AD2` 標成 primary、`#E4F222` 標成 accent／link（B-colors.primary, B-colors.accent / link），但畫面上 `#5E6AD2` 只在產品 UI 截圖裡的送出鈕出現，網站本身的連結（Learn more、View all）是灰色 `#8A8F98`，不是黃綠（P-05, P-09）。**兩者矛盾**：branding 抓到的是產品色，不是官網的 UI 色。另外 B-colors.textPrimary 是 `#08090A`（與背景同色），在深色畫面上不可能是主要文字色，應是萃取到淺色按鈕上的字色（P-07, B-components.buttonPrimary）。
- [I] 官網外殼刻意「無彩」，把彩度全部留給產品畫面與社會證明，讓目光落在產品本身（依據 O：P-03, P-07, P-09, P-10）。

### Typography
- [O] branding 回報字族為 Inter（內文）與 SF Pro Display（標題），兩者堆疊都以 Inter 開頭（B-fonts）；實際字型檔未驗證（X-08）。截圖上大標與內文都是同一套幾何無襯線字形（S-d00, `_slices/dz-hero-top.png`）。
- [O] 另有等寬大寫小字，用於「POWERING THE COMPANIES…」、「FIG 0.1」、Changelog 日期、檔名（S-d00, S-d03）。
- [O] 字級階層（截圖量測，E3；字級本身為推估）：H1 兩行基線間距約 66px（桌機），branding 回報 h1 64px；區塊標題基線間距約 48px，branding 回報 h2 48px；區塊說明約 22px 級、明顯大於內文；內文 branding 回報 15px（S-d00, S-d01, B-typography.fontSizes）。
- [H] 大標題行高接近 1.0、字距收緊，字重中等偏粗而非 Black（E5，從 `_slices/dz-hero-top.png` 目測）；驗證：Playwright 讀 `getComputedStyle(h1)` 的 `line-height`、`letter-spacing`、`font-weight`。
- [O] 陳述段用「同一句話兩種亮度」：前半白色粗體、後半灰色（P-05, M-L94）。
- [O] 區塊標題一律在固定位置斷行成兩行（「Intake / and integrations」「AI and / automations」），markdown 中也保留了雙空格斷點（S-d01, S-d02, M-L125, M-L385）。

### Layout
- [O] 區塊順序：導覽 → Hero（大標＋副標＋產品 UI）→ 客戶 logo → 品牌陳述＋三個價值點（Fig 0.1–0.3）→ 四個產品領域（Intake、Planning、AI、Build）→ Changelog → 見證 → 40,000 數字 → 收尾 CTA → 頁尾（S-d00–S-d04）。
- [O] 四個產品領域區塊高度接近：以分隔線量，Intake 約 1270px、Planning 約 1238px、AI 約 1242px（S-d01, S-d02, P-02 的分隔線位置）。
- [O] 整頁靠左對齊，只有收尾 CTA 置中（S-d00–S-d04）。
- [I] 置中只出現一次，讓收尾 CTA 在長頁末端成為明確的「終點」（依據 O：S-d04）。

### Grid
- [O] 內容寬度：導覽 logo 左緣 x≈320、Sign up 右緣 x≈1600，內容容器約 1280px（S-d00, `_slices/dz-hero-top.png`）。
- [O] 產品領域區塊採「左標題／右說明」兩欄，右欄從 x≈992 起，大約在容器中線（`_slices/dz-intake.png`）。Features 列也對齊同一條右欄線，右欄再分兩小欄、中間有細直線（S-d01, S-d02, S-d03）。
- [O] 產品 UI 截圖會突破容器：Intake 的 Thread 視窗左緣在 x≈297，比文字左緣更外；AI 的四個視窗、Planning 的畫面左右都延伸到容器外並淡出（`_slices/dz-intake.png`, S-d02）。
- [O] 價值點是三欄、Changelog 是四欄、頁尾是 1＋5 欄（S-d00, S-d03, S-d04）。

### Spacing
- [O] branding 回報 baseUnit 4（B-spacing）。
- [O] 產品領域區塊內部節奏一致：分隔線 → 約 170px → 標題 → 約 130px → 產品畫面 → 約 130px → Features 列 → 約 140px → 下一條分隔線（S-d01, S-d02；E3 量測，±10px）。
- [O] 區塊之間有兩段 300px 以上的純留白（y=2404–2740、y=7412–7716），blank 工具確認未延伸到底部，是設計留白而非未載入（observations §1, S-d01, S-d03）。

### Shape
- [O] 按鈕全是膠囊形（radius 9999px），導覽的 Sign up 與收尾 CTA 兩顆都一樣（B-components.buttonPrimary, B-components.buttonSecondary, S-d04）。
- [O] 產品 UI 視窗、見證卡、平板／手機的 Fig 卡片是小圓角（branding 回報 8px）（B-spacing, S-d03, S-t00）。
- [O] 標籤徽章（Bug、Design）在產品 UI 中也是膠囊形（`_slices/dz-intake.png`）。

### Border
- [O] 區塊之間用 1px 全寬細線 `#1B1C1D` 分隔，導覽列底部也有一條（P-02）。
- [O] 欄與欄之間用細直線分隔（Fig 三欄、Features 兩小欄、導覽 Log in 前）（S-d00, S-d01, `_slices/dz-hero-top.png`）。
- [O] 產品面板用比背景亮一級的灰 `#111213`–`#151617` 做出層次，而不是粗外框（P-04）。

### Shadow／Elevation
- [O] branding 回報主要按鈕有 5 層、最高不透明度 8% 的極淡陰影；次要按鈕用內側 3–4% 白描邊＋外側 60% 黑環（B-components.buttonPrimary, B-components.buttonSecondary）。
- [O] Hero 產品 UI 底下有大面積中性灰光暈（P-03, S-d00）；其他產品畫面用四周淡出代替陰影（S-d01, S-d02, S-d03）。
- [I] 高度感靠「亮度差」而非投影：面板比背景亮一級、Hero 用光暈托起，符合深色介面裡陰影不明顯的限制（依據 O：P-03, P-04）。

### Imagery
- [O] 首頁沒有照片、人物插畫或影片；圖像幾乎全是產品 UI（Hero、四個產品領域各一組），另有一組線框 3D 插畫（Fig 0.1–0.3）與單色客戶 logo（S-d00–S-d03, P-12）。
- [O] 產品 UI 中的資料是同一個虛構故事：iOS app 啟動慢 → Slack 討論 → 建 issue → agent 改 code → PR review（M-L13–61, M-L225–249, M-L443–534）。
- [O] 產品 UI 大部分是文字與小圖拼成的 HTML，不是單張圖片；只有 Hero 有兩張 2560 寬大圖（H-02, M-L13–534）。

### Iconography
- [O] 導覽與產品 UI 中的圖示是細線條、單色灰；狀態圖示（In Review 綠、In Progress 黃、Todo 空心圓）帶顏色（S-d00, S-d03）。
- [O] 網站本身的圖示只有箭頭「→」與「+」，以文字字元呈現（M-L129, M-L253, M-L578）。

### Visual hierarchy
- [O] 首屏亮度最高的是 H1（`#F7F8F8`）與 Sign up 按鈕（`#E5E5E6`）；產品 UI 被下方灰色光暈托亮（P-03, P-05, P-07）。
- [I] 第一眼是 H1，第二眼是產品 UI，第三眼才是導覽與「New Loops」。階層幾乎只靠亮度與大小建立，沒有用顏色（依據 O：P-03, P-05, S-d00）。

### Composition
- [O] Hero 文字壓在左上，右側留空；「New Loops →」單獨放在副標同一行最右側（`_slices/dz-hero-top.png`）。
- [O] 產品領域區塊中，產品畫面元素前後疊放（Thread 視窗疊在看板之前、AI 視窗並排且左右淡出）（S-d01, S-d02）。

### Density
- [O] 桌機整頁 10024px 高、11 個段落；每個產品領域區塊只有一個標題、一段說明、一個連結、一組畫面與 3–6 個 Features 項目（S-d00–S-d04, M-L125–550）。
- [I] 文字密度低、畫面密度高：說明句都只有一句，資訊量交給產品畫面承擔，適合「讓人看懂產品長什麼樣」的任務（依據 O：M-L125–129, M-L261–265, S-d01）。

**核心問題的答案**：[I] Linear 首頁的視覺語言是「一個近黑背景＋四級冷灰文字＋膠囊按鈕」的無彩外殼，所有彩度、細節與密度都交給內嵌的產品畫面。外殼負責秩序（固定的左標題／右說明網格、細線分隔、大留白），產品畫面負責吸睛與說服（P-01, P-05, P-09, S-d01）。

## 2. 使用者體驗

### Information Architecture
- [O] 主內容依「產品開發流程」分成四段：Intake（收集需求）→ Planning（規劃）→ AI（代理執行）→ Build（review 與出貨），各自連到 /intake、/plan、/ai、/build（M-L125–439, H-07）。
- [I] 分段依據是工作流程而非功能清單，讀完四段就看完一次「從回饋到出貨」的流程，對應 H1 的「product development system」（依據 O：M-L3, M-L125–439）。

### Navigation
- [O] 桌機導覽：Product、Resources、Customers、Pricing、Now、Contact，加上 Log in 與 Sign up（S-d00）。平板與手機收成漢堡選單，但 Log in 與 Sign up 仍然露在外面（S-t00, S-m00）。
- [O] 有「Skip to content」跳過連結（H-08）。
- [H] 導覽列是否固定在頂部、Product／Resources 是否有下拉，看不到（X-04）；驗證：Playwright 捲動後截圖並 hover 導覽項目。

### User flow
- [O] 轉換出口：Sign up（導覽）、Get started／Contact sales（收尾）、Open app、Download（M-L600, S-d00, S-d04）。
- [O] 中段沒有註冊按鈕；每個產品領域只有「Learn more →」通往深入頁（M-L129, M-L265, M-L389, M-L439）。
- [I] 主要路徑是「首屏 Sign up」或「讀完整頁 → 收尾 Get started」，中段只提供往下深入（領域頁）而不是轉換，兩種讀者（想試用的、想研究的）各有出口（依據 O：M-L600, M-L129–439）。

### Content hierarchy
- [O] 四個產品領域都用同一順序：兩行標題 → 一段說明 → Learn more → 產品畫面 → Features 清單（S-d01, S-d02, S-d03）。
- [I] 結構固定讓讀者在第二段之後就能預期「接下來會看到什麼」，只需要處理內容差異（依據 O：S-d01, S-d02, S-d03）。

### CTA
- [O] 主要按鈕（淺灰膠囊）全頁只出現兩次：導覽 Sign up、收尾 Get started；次要按鈕（深灰膠囊）只有 Contact sales（P-07, P-08, S-d04）。
- [O] 文字連結型 CTA 都是「動詞／名詞＋→」並為灰色：Learn more →、View all →、Customer stories →、Loops →（P-05, M-L7, M-L578, M-L596）。
- [I] 實心按鈕極少，讓「Get started」在長頁末端仍有足夠的視覺分量（依據 O：P-07, S-d04）。

### Affordance
- [O] 可點擊的文字連結全用「→」，可展開的 Features 項目全用「+」（M-L129, M-L253–259, M-L540–550）。
- [O] 產品 UI 看起來可操作（有輸入框、送出鈕、游標），但它是示範畫面（S-d01, M-L61）。
- [H] 產品 UI 不可互動；驗證：Playwright 點擊輸入框與送出鈕，看是否有反應。

### Discoverability
- [O] Features 清單的項目要點「+」才看得到內容（X-05）；手機版完全沒有 Features 列（S-m01）。
- [O] 「New Loops →」放在首屏，新功能入口不用捲動就看得到（S-d00, M-L7）。

### Feedback
- 無法觀察：hover、點擊、載入狀態都看不到（X-02）。

### Form／Error／Success
- [O] 首頁沒有真正的表單（X-10）。

### Cognitive load
- [O] 每屏的選擇數少：首屏只有 Sign up、Log in、Loops 三個非導覽動作；每個產品領域只有一個 Learn more（S-d00, S-d01）。
- [O] 文案有專有名詞門檻：PRD、PR、diff、MCP、Cycles、Triage（M-L116, M-L425–433, M-L538–550）。
- [I] 低選擇數抵銷了專業名詞門檻；用詞假設讀者是軟體團隊，等於主動篩選受眾（依據 O：S-d00, M-L425–550）。

**核心問題的答案**：[I] 設計用「首屏一個主 CTA → 四段固定結構的流程導覽 → 社會證明 → 收尾 CTA」帶讀者走完一次產品開發流程。它降低負擔的方法是固定結構與極少的按鈕；增加負擔的地方是專業名詞與要點開才看得到的 Features（S-d01–S-d04, M-L125–600, X-05）。

## 4. 響應式

三個寬度都有：桌機 1920、平板 768、手機 360。

| 維度 | 桌機 | 平板 | 手機 | 重新分配的邏輯 |
| --- | --- | --- | --- | --- |
| Layout（欄數、對齊、順序） | 產品領域是左標題／右說明兩欄，畫面在文字下方（S-d01） | 標題、說明單欄堆疊，畫面仍在文字下方（S-t01） | 單欄，且**產品畫面移到標題之前**（S-m00, S-m01） | 手機讓畫面先出現，捲動時每段先看到「產品長什麼樣」再讀標題 |
| Typography（字級、斷行） | H1 兩行，基線間距約 66px（S-d00） | H1 兩行，副標斷成兩行（S-t00） | H1 四行，約 40px 級（S-m00, `_slices/mz-top.png`） | 縮字級但保留區塊標題的固定斷行（「Intake / and integrations」三個寬度都一樣） |
| Spacing（邊距、區塊間距） | 容器約 1280px，左右大邊距（S-d00） | 左右約 36px 邊距（S-t00） | 左右約 24px 邊距（S-m00） | 邊距隨寬度縮小，區塊間的分隔線保留（S-m01） |
| Navigation | 6 個項目＋Log in＋Sign up（S-d00） | 漢堡選單＋Log in＋Sign up（S-t00） | 同平板（S-m00） | 收起選單，但轉換按鈕永遠露出 |
| Content priority（提前、刪掉、放大） | 全部區塊（S-d00–S-d04） | 拿掉「40,000」那一行；Changelog 只露出兩則（S-t03） | 拿掉 Features 列、Changelog、「40,000」那一行；頁尾不放 logo（S-m01, S-m02） | 保留「流程四段＋見證＋CTA」主幹，砍掉延伸資訊與次要證據 |
| Components（卡片、按鈕、圖片的變體） | 價值點三欄無外框、細線分隔（S-d00）；產品畫面為多元素組合（S-d01–S-d03） | 價值點變成有外框的卡片（S-t00）；產品畫面裁切或換成較少元素（Planning 只剩散點圖、AI 只剩兩窗）（I-04, I-06） | 產品畫面換成單一焦點元件（AI 段變成「Assign to...」選單、Planning 只剩時間軸）（I-04, I-06） | 寬度越窄，產品畫面越聚焦在一個能看清楚的元件，而不是等比例縮小整個組合 |
| Interaction（hover 改點擊、多欄改滑動） | 價值點三欄並排、見證兩張並排（S-d00, S-d03） | 價值點、見證卡改成橫向排列且被右緣裁切（S-t00, S-t03） | 價值點、見證卡一次一張、右緣露出下一張（S-m00, S-m02） | [H] 多欄內容在窄寬度改成橫向滑動；驗證：Playwright 在手機寬度做水平滑動 |

例外：Hero 產品 UI 在手機上是**整張縮小**而不是換成單一元件，在平板是**右側裁切**（S-m00, S-t00）。

**核心問題的答案**：[I] Viewport 變窄時，Linear 不是把桌機版等比例縮小，而是重新挑選內容：保留四段流程與 CTA 的主幹，刪掉延伸清單（Features、Changelog），並把每段的產品畫面換成一個在窄螢幕仍看得清楚的元件，同時把畫面移到標題之前（S-m01, I-04, I-06）。多欄內容推測改為橫向滑動（[H]，S-t00, S-m00）。

## 5. 模式

本節只從第 1–4 節抽取，不重新分析網站。

### VP-01 無彩外殼，彩度只給產品與證據
- 類型：視覺處理
- 出現位置：背景與文字（P-01, P-05）、按鈕與分隔線（P-02, P-07, P-08）、Hero 光暈（P-03）；彩色出現於產品 UI 送出鈕（P-09）、散點與 diff（S-d02, S-d03）、見證卡（P-10）、Changelog 最新點（P-11）
- 不變的部分：網站本身的元件（背景、文字、按鈕、線、連結）只用灰階
- 會變的部分：彩色的種類隨內容變化（紫、青綠、紅綠、黃綠、藍）
- 推測目的：[I] 讓彩度成為「這裡是產品」或「這裡是證據」的訊號，目光自然落到產品畫面上

### VP-02 四級冷灰文字階層
- 類型：視覺處理
- 出現位置：H1 與頁尾欄標 `#F7F8F8`、區塊說明 `#D0D6E0`、副標／導覽／連結 `#8A8F98`、等寬小標與日期 `#62666D`（P-05, P-06）；陳述段同句雙色（P-05, M-L94）；40,000 一行中數字白、其餘灰（S-d04）
- 不變的部分：只靠亮度分級，不用顏色或底線
- 會變的部分：同一句內可以混用兩級（強調前半或數字）
- 推測目的：[I] 用亮度取代粗體與顏色做強調，讓灰階外殼仍有清楚的閱讀順序

### VP-03 產品領域區塊的固定結構
- 類型：結構
- 出現位置：Intake（S-d01, M-L125–259）、Planning（S-d01–S-d02, M-L261–383）、AI（S-d02, M-L385–433）、Build（S-d02–S-d03, M-L435–550）
- 不變的部分：兩行標題（左）→ 一段說明＋Learn more（右）→ 突破容器的產品畫面 → Features 標籤＋兩小欄「+」清單 → 全寬細線；區塊高度約 1240px
- 會變的部分：產品畫面的形式（對話＋看板、時間軸＋圖表、多窗對話、清單＋diff）與 Features 數量（4–6 個）
- 推測目的：[I] 讓讀者在第二段後就能預測版面，只需處理內容差異；也讓網站團隊可以用同一個區塊模板加新領域

### VP-04 用產品畫面當主視覺，並讓它演一段連續的故事
- 類型：UX 決策
- 出現位置：Hero（S-d00, M-L13–61）、Intake（S-d01, M-L225–249）、Planning（S-d02）、AI（S-d02, M-L391–423）、Build（S-d03, M-L443–534）
- 不變的部分：沒有照片或抽象插圖；畫面是用 HTML 組成的產品介面，資料延續同一個「iOS app 啟動慢」故事
- 會變的部分：每段展示的產品面向
- 推測目的：[I] 讓首頁本身就是產品示範；[H] 畫面會隨時間改變狀態來示範 agent 運作（I-01, I-03），待驗證

### VP-05 文字型 CTA 統一符號：「→」前往、「+」展開
- 類型：互動（affordance）
- 出現位置：Learn more →（M-L129, M-L265, M-L389, M-L439）、View all →（M-L578）、Customer stories →（M-L596）、Loops →（M-L7）；Features「+」（M-L253–259, M-L373–383, M-L427–433, M-L540–550）
- 不變的部分：灰色文字＋字元符號，沒有按鈕外框
- 會變的部分：文案
- 推測目的：[I] 把實心按鈕的分量留給轉換動作，其餘連結用一致的符號告訴讀者點下去會發生什麼

### VP-06 膠囊按鈕只用在轉換，且只分亮／暗兩級
- 類型：視覺處理＋UX 決策
- 出現位置：導覽 Sign up（P-07, S-d00）、收尾 Get started＋Contact sales（P-07, P-08, S-d04）；平板與手機導覽 Sign up（S-t00, S-m00）
- 不變的部分：全圓角膠囊；主要＝淺灰底深字、次要＝深灰底白字；不使用品牌色
- 會變的部分：只有文案
- 推測目的：[I] 按鈕數量少、樣式少，讓「實心膠囊＝轉換」成為整站唯一的意義

### VP-07 用細線與亮一級的灰做結構，不用陰影
- 類型：視覺處理
- 出現位置：導覽底線與區塊分隔線（P-02）、欄間直線（S-d00, S-d01, S-d03）、產品面板 `#111213`–`#151617`（P-04）、Features 兩小欄間的直線（S-d01, S-d02）
- 不變的部分：1px、比背景亮一點點的線或面
- 會變的部分：水平（分區）或垂直（分欄）
- 推測目的：[I] 在深色背景上建立秩序而不增加視覺噪音

### VP-08 窄螢幕重新挑選內容，而不是縮小
- 類型：響應式行為
- 出現位置：Planning 畫面（I-06）、AI 畫面（I-04）、Features 列在手機消失（S-m01）、Changelog 在平板減為兩則、手機消失（S-t03, S-m01）、40,000 一行在平板與手機消失（S-t03, S-m02）
- 不變的部分：四段流程、見證、收尾 CTA 永遠保留
- 會變的部分：延伸資訊（Features、Changelog、數字）與產品畫面的元素數量
- 推測目的：[I] 窄螢幕的空間只留給「每段一個看得清楚的產品元件＋標題＋連結」

### VP-09 手機上畫面先於標題；多欄改為露邊的橫向排列
- 類型：響應式行為
- 出現位置：畫面先於標題：Intake、Planning、AI、Build 四段（S-m00, S-m01）；露邊橫排：價值點卡片（S-t00, S-m00）、見證卡（S-t03, S-m02）、Changelog 時間線延伸出右緣（S-t03）
- 不變的部分：手機上每段第一個出現的是產品畫面；多張卡片在窄螢幕不堆疊，而是右緣露出下一張
- 會變的部分：露出的寬度
- 推測目的：[I] 畫面先行讓捲動時的節奏變成「看 → 讀」；露邊提示還有更多內容。[H] 露邊區可橫向滑動（未驗證）

### VP-10 等寬大寫小字當「註解層」
- 類型：視覺處理
- 出現位置：「POWERING THE COMPANIES…」（S-d00, M-L92）、「FIG 0.1／0.2／0.3」（S-d00, M-L108–119）、Changelog 日期（S-d03）、code 檔名（S-d03, M-L505）
- 不變的部分：等寬字、大寫、最暗一級 `#62666D`（P-06）、小字級
- 會變的部分：內容類型（標籤、圖號、日期）
- 推測目的：[I] 像工程文件的圖說，和主文字明顯分層，也呼應工程師受眾

## 6. 設計語言與設計系統推論

本節只從第 5 節的模式（與少數有證據的 [I]）抽象，不引入新觀察。

| 面向 | 設計語言（一句話） | 根據 |
| --- | --- | --- |
| 色彩哲學 | 外殼是無彩的灰階舞台，彩度是稀缺資源，只發給產品畫面與社會證明 | VP-01, VP-06 |
| 字體哲學 | 一套無襯線字族＋一套等寬字；用亮度而不是字重或顏色分層 | VP-02, VP-10 |
| 版面哲學 | 一個固定的區塊模板重複四次，產品畫面可以突破網格、文字永遠守在網格內 | VP-03, VP-04 |
| 互動哲學 | 動作種類越少越好：實心膠囊只代表轉換，「→」代表前往，「+」代表展開 | VP-05, VP-06 |
| 動態哲學 | [H] 動態是產品示範（狀態推進），不是裝飾 | VP-04（I-01, I-03 待驗證） |
| 響應式哲學 | 窄螢幕重新編輯內容：留主幹、刪延伸、畫面先行、多欄改露邊橫排 | VP-08, VP-09 |
| 資訊層級 | 亮度決定閱讀順序；結構用 1px 細線與亮一級的面建立 | VP-02, VP-07 |

**設計系統推論**（全部是從渲染結果推論，不代表網站有正式設計系統）：

- Tokens：
  - [I] 色彩至少有兩組：「外殼中性色」（`#08090A` 背景、`#111213`–`#151617` 面板、`#1B1C1D` 線、四級文字 `#F7F8F8`／`#D0D6E0`／`#8A8F98`／`#62666D`）與「內容色」（`#5E6AD2`、`#E4F222`、`#EB5757` 等只在產品或證據中出現）（VP-01, VP-02, VP-07）。
  - [H] 字級可能有 display（約 64px）、title（約 48px）、lead（約 22px）、body（約 15px）、caption（等寬小字）五級；只有 64／48／15 有 branding 支撐（E4），其餘是截圖推估（VP-02, VP-10）。
  - [H] 間距以 4 為基準（B-spacing 為 E4），區塊內約 130–170px 的大間距可能是固定 token（VP-03）；驗證：Playwright 讀各區塊的 padding。
  - [I] 圓角至少兩級：膠囊（9999px）給按鈕與徽章、小圓角（約 8px）給面板與卡片（VP-06）。
- Components／Variants：
  - [I] Button：primary（淺灰膠囊）、secondary（深灰膠囊）兩個 variant；文字連結（灰字＋→）可能是第三種（VP-05, VP-06）。
  - [I] Section 模板：FeatureSection（標題、說明、連結、畫面插槽、Features 清單）（VP-03）。
  - [I] Features 清單項目：文字＋「+」的可展開項目（VP-05）。
  - [I] Caption／Eyebrow：等寬大寫小字（VP-10）。
  - [H] Carousel／Marquee：logo 列與見證卡可能是跑馬燈或輪播元件（I-05, H-04），待驗證。
- States：hover、focus、active、disabled、展開後的 Features 項目全部看不到（X-02, X-05）。這是本推論最大的缺口。

## 7. 綜合

- **一句話總結**：Linear 首頁用一個無彩、靠亮度分層的深色外殼，配上一個重複四次的固定區塊模板，把全部的彩度與細節讓給「正在運作的產品畫面」，讓首頁本身就是產品示範。
- **設計原則**（可遷移到其他專案）：
  1. [DP] 把彩度當成稀缺資源：網站外殼用灰階，顏色只出現在產品與證據上，讓顏色本身就有意義（VP-01）。
  2. [DP] 用亮度而不是顏色或粗體建立文字層級，三到四級就夠；同一句話可以用兩級亮度強調重點（VP-02）。
  3. [DP] 為主要內容區設計一個固定模板並重複使用，讀者學一次就能讀完全部，新增內容也不用重新設計版面（VP-03）。
  4. [DP] 用真實的產品介面（最好串成一個連續的使用故事）取代抽象插圖當主視覺（VP-04）。
  5. [DP] 讓每一種視覺樣式只代表一種動作：實心按鈕＝轉換、箭頭＝前往、加號＝展開（VP-05, VP-06）。
  6. [DP] 在窄螢幕重新編輯內容，而不是縮小：保留主幹，刪除延伸資訊，把每段的視覺換成一個看得清楚的元件（VP-08, VP-09）。
- **設計取捨**：
  - 為了外殼的克制，犧牲了品牌色的辨識度：branding 偵測到的品牌紫幾乎不出現在網站本身（P-09, B-colors.primary）。
  - 為了低文字密度，Features 細節藏在「+」後面，手機版甚至完全拿掉，想快速比較功能的讀者要再點進領域頁（X-05, S-m01）。
  - 用詞與示範內容（PR、diff、MCP）假設讀者是軟體團隊，非技術讀者的門檻較高（M-L425–550）。
  - 手機版刪掉 Changelog 與 40,000 數字，等於少了「持續更新」與「規模」兩種證據（S-m01, S-m02）。
- **最值得帶走的一件事**：先把網站外殼做成無彩的舞台，再讓產品畫面成為唯一有顏色、有細節的主角（DP-1、DP-4，來自 VP-01 與 VP-04）。

## 8. 自我審查

1. **證據等級分布**：E1 0 筆、E2 約 31 筆（M- 23、H- 8）、E3 約 36 筆（S- 13、P- 12、I- 6，以及截圖量測）、E4 13 筆（B-）、E5 少數（字重、行高、字級推估）。最弱的環節是**沒有 E1**：字體數值、間距、按鈕樣式都依賴 E4 branding 或 E3 截圖量測；動態完全沒有直接觀察。
2. **只有單一證據或停在 [H] 的重要結論**：
   - 動態哲學整列是 [H]，只靠截圖差異（I-01, I-03）與 markdown 文字（H-05）。
   - 「多欄在窄螢幕可以橫向滑動」是 [H]（VP-09 的後半）。
   - 字級階層中 22px lead 與等寬 caption 的大小是 E5 推估。
   - 「branding primary 是產品色、不是官網 UI 色」的判斷，依據只有一處取樣（P-09）與連結顏色（P-05）。
3. **無法觀察的維度**：X-01（computed style）影響第 1 節的 Typography 與 §6 tokens；X-02（狀態）讓 §6 的 States 完全空白，也讓 UX 的 Feedback 無法評估；X-03 讓第 3 節只能停在 [H]；X-04、X-05 讓導覽與 Features 的互動未知；X-06 讓「手機刪掉區塊」無法區分是不輸出還是隱藏。
4. **是否有重述而非引用**：第 5 節的「出現位置」重列了 P- 色碼，是為了讓模式可單獨閱讀；第 4 節表格最後一欄與 VP-08／VP-09 有重疊，但 VP 只引用證據 ID 並加上不變／會變的規則。第 7 節只引用 VP 編號。
5. **下一次最值得補的證據**：在可以直連的環境用 Playwright：(a) `getComputedStyle` 讀 h1／h2／區塊說明／按鈕／連結；(b) 每 500ms 截圖 Hero 與 Build 段 10 秒，確認狀態推進動畫；(c) hover 導覽、按鈕、Learn more、「+」並點開 Features；(d) 手機寬度水平滑動價值點與見證卡；(e) 以 `reducedMotion: 'reduce'` 重新截圖比對。
