# Linear 首頁：設計師摘要

> 研究日期 2026-10-01。這是 [完整研究報告](report.md) 的摘要，每一點都可以點進去看證據。只研究首頁；網站直連被擋，所有數值都來自三個寬度（1920／768／360）的截圖與頁面文字，沒有讀到實際的 CSS。

## 這個網站在做什麼
Linear 是給軟體團隊用的產品開發工具。首頁的任務是讓訪客看懂「從收集需求到出貨」的整套流程，然後按 Sign up 或在頁尾按 Get started；用詞（PR、diff、MCP）明顯是寫給工程團隊看的。

## 最值得學的設計決定
1. **無彩的外殼，顏色只給產品和證據**：整頁只有一個近黑背景 `#08090A`，文字只用四級冷灰（`#F7F8F8`／`#D0D6E0`／`#8A8F98`／`#62666D`），按鈕和分隔線也都是灰。彩色出現在產品畫面（紫色送出鈕、紅綠 diff、黃色狀態圖示）、見證卡（黃綠、淺藍）；網站本身唯一的例外是 Changelog 時間線最新一則的紅點。顏色因此變成「這裡是產品／這裡是證據」的訊號，層級改用亮度和大小建立。
   可信度：色碼是截圖上量得到的；「刻意讓目光落到產品」是推論。→ [report §5 VP-01](report.md#vp-01-無彩外殼彩度只給產品與證據)、[VP-02](report.md#vp-02-四級冷灰文字階層)
2. **用產品畫面當主視覺，而且串成同一個故事**：首頁沒有照片或抽象插圖（見證卡上也只有公司 logo，沒有人像），Hero 和四個產品段落各放一組用 HTML 拼成的產品介面，資料延續同一個「iOS app 啟動慢 → Slack 討論 → 建 issue → agent 改 code → PR review」的情境，畫面還會突破文字的容器寬度、四周淡出。首頁本身就是產品示範。
   可信度：畫面內容與故事截圖和頁面文字上看得到；畫面「會動、會推進狀態」是推測，還沒驗證。→ [report §5 VP-04](report.md#vp-04-用產品畫面當主視覺並讓它演一段連續的故事)
3. **一個區塊模板重複四次**：Intake、Planning、AI、Build 四段都是「左邊兩行標題 → 右邊一句說明＋Learn more → 產品畫面 → Features 清單 → 1px 全寬分隔線」，每段高度約 1240px，內部間距約 170／130／130／140px。讀者看完第二段就能預期版面，只需要處理內容差異；團隊加新段落也不用重新排版。
   可信度：截圖上量得到（間距誤差約 ±10px）。→ [report §5 VP-03](report.md#vp-03-產品領域區塊的固定結構)
4. **一種樣式只代表一種動作**：桌機版整頁的實心膠囊按鈕只有導覽的 Sign up、收尾的 Get started（淺灰）和 Contact sales（深灰），都用在轉換，也都不用品牌色（產品畫面裡的按鈕不算）；其餘連結一律是灰字加「→」（前往），可展開的 Features 項目一律是「+」。按鈕少，頁尾的 Get started 在長頁末端仍然有分量。
   可信度：從截圖和頁面文字看得到；hover、點擊後的樣子完全沒看到。→ [report §5 VP-05](report.md#vp-05-文字型-cta-統一符號前往展開)、[VP-06](report.md#vp-06-膠囊按鈕只用在轉換且只分亮暗兩級)
5. **窄螢幕重新編輯內容，而不是等比縮小**：手機版保留四段流程、見證和收尾 CTA，拿掉 Features 清單、Changelog 和「40,000 teams」那一行；四個產品段落的畫面改成一個看得清楚的元件（例如 AI 段只剩「Assign to...」選單），並且放到標題之前，讓捲動節奏變成「先看再讀」；多張卡片改成一次一張、右緣露出下一張。例外是 Hero 的產品畫面在手機上是整張縮小、在平板是右側裁切。
   可信度：三個寬度的截圖比對看得到；卡片能否橫向滑動是推測，還沒驗證。→ [report §5 VP-08](report.md#vp-08-窄螢幕重新挑選內容而不是縮小)、[VP-09](report.md#vp-09-手機上畫面先於標題多欄改為露邊的橫向排列)

## 代價與不要照抄的地方
- **品牌色幾乎看不到**：Linear 的品牌紫只出現在產品畫面裡的一顆送出鈕。這套做法建立在「產品畫面本身夠好看、夠有顏色」上；如果你的產品介面平淡，外殼全灰會讓整頁沒有記憶點。
- **功能細節藏起來了**：Features 要點「+」才看得到，手機版整個拿掉，想快速比較功能的人得再點進領域頁。
- **門檻是刻意的**：PR、diff、MCP 這類用詞只對軟體團隊友善；受眾比較廣的產品不適合照抄文案策略。
- **手機少了兩種證據**：拿掉 Changelog 和「40,000」等於少了「持續更新」與「規模」的說服力。
- 以上取捨見 [report §7 綜合](report.md#7-綜合)。

## 還不確定的事
- **動態完全沒有直接觀察**：「產品畫面會演出 agent 從思考到完成」只是從不同次擷取的畫面差異推來的，觸發方式、時長、easing 都不知道。要驗證：在能直連的環境用 Playwright 每 500ms 截圖 Hero 與 Build 段 10 秒。→ [report §3](report.md#3-動態)
- **互動狀態是空白**：hover、focus、導覽下拉、Features 展開後的樣子都沒看到，設計系統推論缺了 States 這一塊。
- **字級與間距沒有實際 CSS**：64／48／15px 來自 branding 萃取，22px 說明字級、行高、字距是看截圖推估的；要用 `getComputedStyle` 確認後再當成規格。→ [report §8 自我審查](report.md#8-自我審查)
