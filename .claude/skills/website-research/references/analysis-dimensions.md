# 分析維度清單

第 3 階段（維度分析）使用。每個維度都要給出結論，或明確寫「無法觀察」並登記 `X-` 缺口——
「沒提到」和「看過但沒有」對讀者是不同的資訊。

每一節的最後，用 1–3 句 `[I]` 回答該節的**核心問題**。核心問題才是這一節的目的，清單只是確保不漏看。

## 目錄
1. 商業／轉換（Business／Conversion）
2. 品牌／風格（Brand／Style）
3. 視覺（Visual）
4. 使用者體驗（UX）
5. 動態（Motion）
6. 響應式（Responsive）

**為什麼是這個順序**：先知道網站想達成什麼（商業），再知道它想讓人怎麼感受這個品牌（品牌），後面四節才有判斷標準：視覺、UX、動態、響應式都是在實現前兩者。

**各節的分工**（避免同一件事寫兩次）：

| 節 | 回答的問題 | 不寫什麼 |
|---|---|---|
| 商業／轉換 | 網站要訪客最後做什麼？怎麼設計說服與轉換？ | 不寫 CTA 的視覺樣式細節（留給視覺）、不寫操作回饋（留給 UX） |
| 品牌／風格 | 這些選擇共同傳達什麼品牌個性與定位？文案語氣如何配合？ | 不重新列色碼、字級（引用視覺節或證據 ID 即可） |
| 視覺 | 具體用了什麼視覺元素、各自承擔什麼功能？ | 不下品牌定位的結論 |
| UX | 使用者怎麼操作、怎麼找到東西、在哪裡被卡住？ | 不重寫轉換策略，引用商業節即可 |
| 動態 | 動態承擔什麼功能？ | — |
| 響應式 | 寬度改變時什麼被重新分配？ | 只寫「隨寬度改變的部分」 |

---

## 1. 商業／轉換

**核心問題：這個網站如何把訪客從「看到網站」引導到「完成商業目標」？**

**不能聲稱效果**：沒有 analytics、A/B test 或實際轉換資料，就不能寫「這個設計提高了轉換率」「有效提升轉換」。
只能寫四種說法：
- **轉換策略**（Conversion strategy）：網站選擇怎麼說服，例如「先建立慾望、價格延後到 FAQ」。
- **轉換機制**（Conversion mechanism）：具體用什麼元素推動，例如「同一顆 CTA 出現在每段結尾」。
- **轉換假設**（Conversion hypothesis）：設計背後可能的推論，例如「假設訪客先被產品物件吸引，才會在意價格」；一律標 `[H]`，並寫出要什麼資料才能驗證（通常是 analytics 或 A/B test，研究本身無法驗證）。
- **可觀察的阻力**（Observable friction）：從頁面上看得到、可能增加轉換阻力的地方，例如「CTA 文字是『申請』，實際開到 App 商店」。

| 維度 | 要回答的問題 |
|---|---|
| Business goal | 網站的主要商業目標（銷售、名單、預約、下載、品牌認知、招募…），依據是什麼文案或 CTA |
| Page goal | 這一頁希望訪客最後做什麼（可能和整站目標不同） |
| Target audience | 理想客戶是誰；從文案用詞、價格帶、案例、CTA 推得（多數是 `[H]`，網站自己寫明才是 `[O]`） |
| Primary CTA | 主要 CTA 的文案、目標（連到哪裡、開什麼）；文案說的動作和實際行為是否一致 |
| CTA placement & frequency | 每個 CTA 出現的位置與次數（列出段落），桌機與手機是否不同；是否有常駐 CTA |
| CTA copy & hierarchy | 文案動詞與承諾；主要與次要 CTA 在大小、對比、位置上的層級 |
| Secondary CTA | 有沒有次要 CTA（例如「了解更多」「預約展示」），它和主要 CTA 是分流、降低門檻還是互相競爭 |
| Conversion path | 從進站到完成主要行動的主要路徑；需要幾步（點擊、頁面、表單欄位）才完成 |
| Funnel | 頁面段落如何對應「注意 → 興趣 → 慾望 → 信任 → 行動」；哪一段缺席或順序特別 |
| Desire building | 哪些內容在建立需求或慾望（主視覺、產品示範、情境、成果） |
| Trust building | 哪些內容在建立信任：Social proof、Testimonials、客戶 logo、數據、Credentials、媒體、認證、團隊 |
| Objection handling | 哪些內容在消除疑慮；FAQ 回答的是哪些轉換阻礙（價格、安全、退款、適用對象） |
| Pricing／Product information | 價格與產品規格放在哪裡、多早出現、是公開還是要聯絡才知道 |
| Conversion friction | 可觀察的阻力：步驟多、資訊不足、CTA 文案與行為不一致、必須離站、表單過長、價格隱藏 |

本節最後，用一句話把路徑寫出來，例如：「進站 → 主視覺建立慾望 → 三個賣點 → 客戶 logo 建立信任 → FAQ 處理價格疑慮 → 同一顆 CTA（第 5 次出現）」。

## 2. 品牌／風格

**核心問題：這個網站的整體風格是什麼？它想讓誰產生什麼感受？透過哪些設計手段建立這種感受？**

**區分兩層**：
- **視覺特徵**（Visual characteristics）：網站使用了什麼。這是 `[O]`，直接引用視覺節或證據 ID，不重新描述。
- **品牌／風格詮釋**（Brand／Style interpretation）：這些選擇共同傳達什麼品牌個性與定位。這是 `[I]` 或 `[H]`。

品牌定位、品牌想建立的形象、目標客群的感受，除非網站自己寫明（`M-`），否則都是詮釋。
寫成「可能」「推測」「從……可以觀察到」，並指出根據的觀察；只有單一觀察時停在 `[H]`。

**Brand Positioning**

| 維度 | 要回答的問題 |
|---|---|
| Intended feeling | 網站想讓訪客感受到什麼（信任、渴望、好奇、安心、興奮、專業…），根據什麼 |
| Brand image | 品牌可能想建立的形象（例如「精品物件」「工程師的工具」「親切的鄰居」） |
| Audience × tone | 目標客群與品牌語氣的關係：語氣是否符合 §1 推得的客群 |
| Style traits | 落在哪些風格特徵：Premium／Mass／Technical／Playful／Professional／Experimental…（可以多選，寫出根據） |
| Personality | 如果品牌是一個人，它的個性（例如「冷靜、少話、有自信」），附根據 |
| Mood | 整體情緒與氛圍，以及最主要靠哪個元素建立 |

**Verbal Style**

| 維度 | 要回答的問題 |
|---|---|
| Headline tone | 標題的語氣：宣言、提問、承諾、描述、口號 |
| CTA tone | CTA 的語氣：命令、邀請、排他（「申請資格」）、低門檻（「先看看」） |
| Copy length | 文案長短；短句還是段落；資訊密度 |
| Person | 第一人稱（我們）、第二人稱（你）、無人稱 |
| Register | 偏理性、情緒、權威、幽默、直接、詩意…，附例句的證據 ID |
| Copy × visual | 文案風格如何配合視覺風格（例如「極簡視覺配上極短標題」） |

**Visual Style**：說明下列元素如何**共同**建立品牌感。每一項只寫「它對品牌感的貢獻」，數值與細節引用視覺節：
Color、Typography、Photography、Illustration、Iconography、Shape、Layout、Motion、Texture、Space。
沒有使用的元素也寫一句（例如「沒有插畫，品牌感全部交給攝影」），因為不用也是選擇。

## 3. 視覺

**核心問題：這些視覺選擇共同形成什麼視覺語言？各自承擔什麼功能？**

| 維度 | 要回答的問題 |
|---|---|
| Color | 色彩角色（背景、文字層級、強調、狀態）；彩度集中在哪裡；明暗模式 |
| Typography | 字族數量與角色；字級階層（列出實際數值）；字重、字距、行高的策略 |
| Layout | 區塊順序與各自高度；對齊方式（靠左／置中）在哪裡改變、為什麼 |
| Grid | 內容最大寬度；欄數與常見欄位配置 |
| Spacing | 基準單位；區塊內與區塊間的間距比例 |
| Shape | 圓角層級（按鈕、卡片、圖片是否不同） |
| Border | 分隔用線、外框還是背景色差 |
| Shadow／Elevation | 有沒有層級；用陰影、光暈還是色差表現 |
| Imagery | 照片、插畫、產品 UI、3D、影片的比例與角色 |
| Iconography | 線條或填色、粗細、是否跟字型協調 |
| Visual hierarchy | 第一眼、第二眼看到什麼；靠大小、亮度、顏色還是位置建立 |
| Composition | 畫面重心、留白分佈、元素疊放 |
| Density | 每屏資訊量；長頁還是短頁；和頁面任務是否相符 |

## 4. 使用者體驗

**核心問題：使用者如何操作、找到需要的資訊並完成任務？在哪裡降低或增加了操作負擔？**

轉換策略、CTA 的出現次數與信任元素寫在 §1；這一節看的是「操作與理解」本身，需要時引用 §1。

| 維度 | 要回答的問題 |
|---|---|
| Information Architecture | 內容分段的依據（依產品、客群、流程、動作？） |
| Navigation | 主選單項目；手機收合方式；捲動後導覽怎麼變 |
| User flow | 完成任務時實際要經過的操作（捲動、展開、切換、離站）；有幾條分支（自助、業務、文件） |
| Content hierarchy | 每段的「標題 → 說明 → 證據 → 行動」結構是否一致 |
| CTA usability | CTA 是否容易找到、點得到（大小、位置、對比）；點下去的結果是否在預期中 |
| Affordance | 什麼東西看起來可以點、可以展開、可以拖曳；線索是什麼 |
| Discoverability | 重要功能是否需要捲很深、點開才看得到 |
| Feedback | 操作後的回饋（hover、點擊、載入狀態）；看不到就登記 X- |
| Form | 頁面上的表單或輸入框；欄位數、說明、預設值 |
| Error／Success states | 看得到才寫，看不到登記 X- |
| Cognitive load | 每屏要處理的選擇數；專有名詞門檻；頁面長度 |

## 5. 動態

**核心問題：動態在這個網站承擔什麼功能（引導注意、示範產品、回饋、建立品牌氛圍、推動轉換）？**

靜態截圖拍不到動態，所以每一項動態都要先說明證據來源：
- 直接觀察：Playwright 操作（`I-`）、錄影
- 間接證據：不同時間的截圖不一樣、markdown 出現狀態文字（「Loading」「Drop to deploy」）、檔名（`fallback-*.webp`）、截圖大段空白（`X-`）
- 沒有證據：不要寫

每一項動態用下表描述，看不到的欄位寫「未觀察」：

| 欄位 | 說明 |
|---|---|
| Trigger | 載入、捲動進入畫面、hover、focus、點擊、時間、狀態改變 |
| Target | 哪個元素 |
| Property | 透明度、位移、縮放、顏色、內容替換、光影 |
| Duration／Easing／Delay | 多久、什麼曲線、延遲多少（靜態資料幾乎一定是「未觀察」） |
| Sequence | 多個元素的先後順序（逐字、逐卡） |
| 推測目的 | `[I]` 或 `[H]`；如果是在強化品牌感（§2）或推動轉換（§1），寫出對應的是哪一點 |

另外檢查這些類別有沒有出現：Hover、Focus、Scroll、Loading、State transition、Page transition，以及是否支援 `prefers-reduced-motion`（有暫停鈕也算證據）。

## 6. 響應式

**核心問題：Viewport 改變時，設計系統如何重新分配資訊、空間與互動？轉換路徑與品牌感有沒有被保留？**

至少比較三個寬度：桌機（1440 或 1920）、平板（768）、手機（360–390）。
沒抓到平板就登記 `X-`，並說明哪些結論因此只能推到「桌機 → 手機」。

用下表整理，每格寫「怎麼變」，不變也要寫「不變」：

| 維度 | 桌機 | 平板 | 手機 | 重新分配的邏輯 |
|---|---|---|---|---|
| Layout（欄數、對齊、順序） | | | | |
| Typography（字級、斷行） | | | | |
| Spacing（邊距、區塊間距） | | | | |
| Navigation | | | | |
| Content priority（什麼被提前、刪掉、放大） | | | | |
| Components（卡片、按鈕、圖片的變體） | | | | |
| Interaction（hover 改成點擊、多欄改成滑動） | | | | |
| Conversion（CTA 的位置、次數、是否常駐） | | | | |
| Brand expression（主視覺、攝影、動態是否保留） | | | | |

最後一欄最重要：說明「為什麼這樣分配」，例如「手機上刪掉延伸句、保留主句，把首屏讓給 CTA」。
